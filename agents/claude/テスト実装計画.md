# bacli-py テスト実装計画

## 概要

bacli-pyの既存機能に対するテスト実装計画です。pytest + pytest-httpx を使用してユニットテストと統合テストを実装します。

## テスト対象モジュール

| モジュール | 機能 | テスト優先度 |
|-----------|------|-------------|
| `config/settings.py` | 設定読み書き | 高 |
| `api/client.py` | HTTPクライアント | 高 |
| `api/rate_limit.py` | レート制限 | 中 |
| `resolver/cache.py` | キャッシュ管理 | 高 |
| `resolver/*.py` | 名前→ID解決 | 高 |
| `models/*.py` | データモデル | 中 |
| `cli/*.py` | CLIコマンド | 中 |
| `utils/formatter.py` | 出力フォーマット | 低 |

## テスト方針

### 1. ユニットテスト
- 外部依存なしでテスト可能な機能
- モック/スタブを使用してAPIレスポンスをシミュレート

### 2. 統合テスト
- CLIコマンドの動作確認（typer.testing.CliRunner使用）
- 実際のファイルシステム操作（tmpdir使用）

### 3. 除外項目
- 実際のBacklog APIへの接続テスト（E2Eテストは別途）

## テストディレクトリ構成

```
tests/
├── conftest.py              # 共通フィクスチャ
├── fixtures/                # テスト用JSONデータ
│   ├── projects.json
│   ├── issues.json
│   └── users.json
├── unit/
│   ├── test_settings.py     # 設定管理
│   ├── test_client.py       # HTTPクライアント
│   ├── test_rate_limit.py   # レート制限
│   ├── test_cache.py        # キャッシュ
│   ├── test_resolvers.py    # Resolver
│   └── test_models.py       # データモデル
└── integration/
    ├── test_cli_auth.py     # authコマンド
    ├── test_cli_project.py  # projectコマンド
    └── test_cli_issue.py    # issueコマンド
```

## 実装フェーズ

### Phase 1: テスト基盤構築
- pytest, pytest-httpx, pytest-cov を依存に追加
- conftest.py で共通フィクスチャ定義
- テスト用JSONフィクスチャ作成

### Phase 2: ユニットテスト（コア機能）
- `test_settings.py`: 設定の保存・読込
- `test_cache.py`: キャッシュのTTL管理、永続化
- `test_models.py`: Pydanticモデルのバリデーション

### Phase 3: ユニットテスト（API層）
- `test_client.py`: HTTPリクエスト、エラーハンドリング
- `test_rate_limit.py`: 429リトライ、指数バックオフ
- `test_resolvers.py`: 名前解決、キャッシュ連携

### Phase 4: 統合テスト（CLI）
- `test_cli_auth.py`: login, logout, status
- `test_cli_project.py`: list, info, types
- `test_cli_issue.py`: list, view, open

## テスト実行コマンド

```bash
# 全テスト実行
uv run pytest

# カバレッジ付き
uv run pytest --cov=bacli_py --cov-report=html

# 特定のテストのみ
uv run pytest tests/unit/test_settings.py

# 詳細出力
uv run pytest -v
```
