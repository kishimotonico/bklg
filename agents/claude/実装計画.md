# bklg-py 実装計画

Backlog CLI ツール（bklg）の実装計画です。全体を「設計フェーズ」と「コーディングフェーズ」に分けて進めます。

## 技術スタック

- **CLIフレームワーク**: Typer
- **TUI**: Textual
- **HTTPクライアント**: httpx
- **データモデル**: Pydantic v2
- **Python**: 3.11+

## フェーズ1: 全体設計（設計フェーズ）

### 1.1 プロジェクト構成の設計

```
src/bklg_py/
├── __init__.py
├── main.py                    # CLIエントリポイント
├── cli/                       # CLIコマンド定義
│   ├── __init__.py
│   ├── auth.py               # bklg auth login/logout/status

│   ├── comment.py            # bklg issue comment add
│   └── api.py                # bklg api <endpoint>
├── api/                       # API通信層
│   ├── __init__.py
│   ├── client.py             # HTTPクライアント（httpx wrapper）
│   ├── auth.py               # 認証ハンドラ
│   └── rate_limit.py         # レート制限・リトライロジック
├── models/                    # Pydanticデータモデル

│   ├── issue.py

│   ├── __init__.py
│   ├── base.py               # 基底Resolver
│   ├── project.py            # プロジェクト名→ID
│   ├── issue_type.py         # 種別名→ID
│   ├── priority.py           # 優先度名→ID
│   ├── user.py               # ユーザー名→ID
│   └── cache.py              # キャッシュ管理
```

### 1.2 主要コンポーネントの責務定義

| コンポーネント | 責務 |
|---------------|------|
| `api/client.py` | HTTPリクエスト送信、フォームエンコード変換、エラーハンドリング |
| `resolver/` | 名前→IDの解決、キャッシュ管理（24h有効） |
| `cli/` | コマンドラインインターフェース、引数パース |
| `tui/` | 対話モード、プロンプト表示 |
| `models/` | APIレスポンスのバリデーション・型定義 |
| `config/` | 認証情報・スペースURL等の永続化 |

### 1.3 設定ファイル仕様

```
~/.config/bklg/
├── config.toml     # スペースURL、デフォルトプロジェクト等
├── credentials     # APIキー（暗号化推奨）
└── cache/          # メタデータキャッシュ
    └── metadata.json
```

## フェーズ2: コーディング（実装フェーズ）

調査レポートの開発ロードマップに沿って、5つのサブフェーズに分けます。

### 2.1 APIクライアント基盤（Phase 1）

**対象ファイル**:
- `src/bklg_py/api/client.py`
- `src/bklg_py/api/auth.py`
- `src/bklg_py/api/rate_limit.py`
- `src/bklg_py/config/settings.py`
- `src/bklg_py/models/common.py`

**実装内容**:
1. 設定ファイル読み書き（スペースURL、APIキー）
2. httpxベースのHTTPクライアント
   - `application/x-www-form-urlencoded` への自動変換
   - APIキー付与
   - エラーレスポンスのパース
3. レート制限対応
   - `X-RateLimit-*` ヘッダー監視
   - 429ステータス時の自動リトライ（指数バックオフ）
4. `bklg auth status` コマンド（疎通確認用）

### 2.2 Read機能とResolver（Phase 2）

**対象ファイル**:
- `src/bklg_py/resolver/*.py`
- `src/bklg_py/cli/project.py`
- `src/bklg_py/models/project.py`
- `src/bklg_py/models/user.py`

**実装内容**:
1. プロジェクト一覧取得 `GET /api/v2/projects`
2. 種別一覧取得 `GET /api/v2/projects/:id/issueTypes`
3. 優先度一覧取得 `GET /api/v2/priorities`
4. ユーザー一覧取得 `GET /api/v2/users`
5. Resolverクラス実装
   - プロジェクトキー→ID解決
   - 種別名→ID解決
   - ユーザー名→ID解決
6. キャッシュ機構（24時間有効、手動更新可能）
7. `bklg project list` コマンド
8. `bklg project info <id>` コマンド

### 2.3 Issue List & View（Phase 3）

**対象ファイル**:
- `src/bklg_py/cli/issue.py`
- `src/bklg_py/models/issue.py`
- `src/bklg_py/utils/formatter.py`

**実装内容**:
1. 課題一覧取得 `GET /api/v2/issues`
   - ページネーション対応
   - フィルタリングオプション（--project, --status, --assignee等）
2. 課題詳細取得 `GET /api/v2/issues/:id`
3. Markdownレンダリング（Rich使用）
4. `bklg issue list` コマンド
5. `bklg issue view <id>` コマンド

### 2.4 Write機能とインタラクション（Phase 4）

**対象ファイル**:
- `src/bklg_py/cli/issue.py`（追加）
- `src/bklg_py/cli/comment.py`
- `src/bklg_py/tui/prompts.py`

**実装内容**:
1. 課題作成 `POST /api/v2/issues`
   - フラグモード（--project, --type, --title等）
   - 対話モード（TUI）
2. 課題更新 `PATCH /api/v2/issues/:id`
3. コメント投稿 `POST /api/v2/issues/:id/comments`
   - メンション自動解析（@user → notifiedUserId）
4. `bklg issue create` コマンド
5. `bklg issue update` コマンド
6. `bklg issue comment add` コマンド

### 2.5 Raw API & 高度な機能（Phase 5）

**対象ファイル**:
- `src/bklg_py/cli/api.py`
- `src/bklg_py/utils/git.py`

**実装内容**:
1. Raw APIアクセス
   - エンドポイント補完
   - メソッド推論（GET/POST）
   - ページネーション抽象化（--paginate）
   - jqフィルタ対応
2. Gitコンテキスト自動認識
   - .git/configからBacklogプロジェクト推論
3. `bklg api <endpoint>` コマンド

## 優先度と依存関係

```
Phase 1 (APIクライアント基盤)
    ↓
Phase 2 (Resolver)
    ↓
Phase 3 (Issue List/View) ← ここまでがMVP
    ↓
Phase 4 (Write機能)
    ↓
Phase 5 (高度な機能)
```

## MVP（最小実用製品）の範囲

Phase 1〜3を完了すれば、以下が動作するMVPとなります：
- `bklg auth status`
- `bklg project list`
- `bklg issue list --project <KEY>`
- `bklg issue view <KEY-123>`
